# Experimental results

This directory stores the outputs of the clickbait-resolution experiments.
Results are separated by evaluation setting:

| Directory | Setting | Contents |
| --- | --- | --- |
| `zs_results/` | Zero-shot (ZS) inference | Model responses and ROUGE metrics. |
| `sft_results/` | Supervised fine-tuning (SFT) | Test-set predictions and ROUGE metrics. |

## Directory structure

```text
results/
├── README.md
├── zs_results/
│   ├── <model>_<approach>_responses.csv
│   └── <model>_<approach>_metrics.csv
└── sft_results/
    ├── <model>_<approach>_predictions.csv
    ├── <model>_<approach>_metrics.csv
    ├── data_dir/
    │   ├── train.jsonl
    │   ├── val.jsonl
    │   └── test.jsonl
    └── runs/
```

`<model>` is the normalized model name used by the scripts, such as
`qwen_3_4b_it` or `gemma_2_2b`. `<approach>` is either `qa` for the
question-answering formulation or `summ` for headline-conditioned
summarization.

## Zero-shot results

Each ZS run produces two CSV files:

| File suffix | Description |
| --- | --- |
| `_responses.csv` | One generated response per test example. |
| `_metrics.csv` | Aggregate ROUGE scores for the run. |

Response files contain these columns:

| Column | Description |
| --- | --- |
| `Title` | Clickbait headline from the test set. |
| `Response` | Text generated by the model. |

Metric files contain `metric` and `score` columns. The reported metrics are
ROUGE-1, ROUGE-2, ROUGE-L, and ROUGE-Lsum.

## Supervised fine-tuning results

Each SFT run produces a prediction file and a metric file:

| File suffix | Description |
| --- | --- |
| `_predictions.csv` | Generated predictions for the test split, in dataset order. |
| `_metrics.csv` | Aggregate ROUGE scores for the test split. |

SFT prediction files contain a `Response` column with generated text, ordered
to match the test split. SFT metric files use the same `metric` and `score`
fields as ZS metric files. All result CSV files are written without a Pandas
index column.

`data_dir/` contains derived JSONL train, validation, and test files created
from the source CSV during SFT. It is an intermediate artifact and can be
regenerated. `runs/`, when present, contains the checkpoints and trainer
artifacts produced by DeepSpeed/TRL.

## Reproducing outputs

Run the commands documented in `../code/README.md`.
Both ZS and SFT scripts create their output directory automatically; use
`--save_path` to select a different location.
